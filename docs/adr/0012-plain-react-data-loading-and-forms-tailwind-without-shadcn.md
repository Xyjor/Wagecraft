# ADR-012: Plain React data loading and forms; Tailwind without shadcn/ui

- **Status:** Accepted (Oct 2026). Supersedes the library list in [ADR-011](0011-react-typescript-tanstack-query-shadcn-ui.md); React 19 + TypeScript strict and Recharts stand.
- **Context:** ADR-011 planned TanStack Query, React Hook Form + Zod, TanStack Table and shadcn/ui. shadcn's site was unreachable from the build environment, so `shadcn init` never ran, and the first screens showed that a one-user desktop app whose screens load once on open did not need a query cache or a form library.
- **Decision:** Screens load data with `useEffect` and a thin `call()` wrapper over Tauri's `invoke` (`src/lib/ipc.ts`), which turns every rejection into an `AppError`. Forms are plain HTML forms read with `formValues()` and checked with zod schemas, with server-side field errors mapped back by `serverErrors()`. Tables are plain HTML. Styling is Tailwind v4 with a few shared components in `src/components/`. Charts use Recharts, PDFs `@react-pdf/renderer`, routing React Router.
- **Alternatives:** _TanStack Query_: caching and invalidation that no screen needed; it would have added a second place where data lives. _React Hook Form_: the forms are short and already validated in Rust, so the gain was small. _shadcn/ui_: still an option; it can be added on a Windows machine where its site is reachable, one component at a time.
- **Consequences:** ➕ fewer dependencies, simpler tests (mock `call`, render, assert), one way to load and one way to submit across 20+ screens. ➖ each screen refetches on open (fine at this data size); form boilerplate is kept small by the shared helpers rather than removed; the UI is plain Tailwind, so visual polish is by hand.
